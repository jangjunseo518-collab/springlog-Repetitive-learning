## [설계 의도와 빌드 순서]
- 공개 여부와 카테고리는 정해진 선택지 내에서 고르는 거기 때문에,  
  각각 enum클래스로 만들어서 상수로 관리하도록 했다.
- 생성 시간, 변경 사간, 테이블pk는 각각 모든 테이블이 갖는 공통 컬럼이기 때문에,   
  불필요한 반복 작업을 방지하기 위해 BasicEntity클래스를 따로 선언하여  
  JPA를 이용해 값을 DB에서 자동으로 생성하도록 한다. 자연스럽게 책임 분리 원칙(SRP)도 지켜진다.  
  추가로 BasicEntity가 객체로 사용되도 아무런 의미가 없으니까 abstract로 선언하여 new로 객체 생성하는 것을 차단한다.
- 스태틱을 적극 사용하여 메서드의 의미을 명확히함
-

### [느낀 점] : 어노테이션도 익숙해졌고, 계층 분리도 요구사항에 맞춰서 설계할 수 있게된거 같다.
<br>

```angular2html
public void changeTitle(String newTitle) {
validationTitle(newTitle);  // 여기서 한 번 쓰임 (검증에만 사용됨)
this.title = title.trim(); <- newTitle을 안 쓰고 다른 필드(title)를 참조
}
```
- [파라미터 사용 안함]: 파라미터의 변수 명을 title로 코드를 만든 뒤에 의미적으로 명확히 하기 위해 newTitle로 변경하는 과정에서  
  검증에만 새로문 변수 명을 썼고, 실제 필드에 할당하는 값으로 사용하지 않았다. 컴파일 에러로 알려주지 않으니까 이 부분 주의하자
